# レビュー記録の書式（正本）

improvement-work 手順 6 がレビューを 1 巡行うたびに notes へ残す記録の書式と、その記録を照合する規則の正本。
書き手の `improvement-work/SKILL.md` 手順 6 と、読み手の `improvement-dispatch/SKILL.md` 手順 6 は、書式を手元に複製せずこのファイルを参照する。
照合の機械的な部分は `claude-code/skills/improvement-dispatch/scripts/check-review-records` が実装している。
書式を変えるときは、このファイル・スクリプト・`tests/test_check_review_records.sh` を同時に直す。

## 書式

1 巡につき 1 つの記録を、`backlog task edit TASK-<n> --append-notes` で notes に追記する。
`<…>` は書き込む内容の説明で、`独立サブエージェント | 自己レビュー` はどちらか一方を書く。
improvement-work 手順 6 の append-notes の例は、この 5 行と一字一句同じにしてある（`tests/test_check_review_records.sh` が検査する）。

```text
### レビュー <巡数> 巡目
- 方法: 独立サブエージェント | 自己レビュー
- 自己レビューにした理由: <Agent ツールが無い / Agent ツールの呼び出しが 2 回続けて失敗した（各回のエラー内容）。独立サブエージェントなら「該当なし」>
- 結果: P0 <件数> / P1 <件数> / P2 <件数> / P3 <件数>（指摘が無ければ No findings）
- 対応: <直した指摘と直し方。見送った P3、妥当でないと判断した指摘とその根拠>
```

- 見出しは `### レビュー <巡数> 巡目` とする。巡数は 1 から数える半角の整数で、前後に半角スペースを 1 つずつ置く。
- 本文は上の 4 行をこの順に書く。各行は `- <項目名>: ` で始める（半角のハイフン・コロン・スペース）。4 行とも省略しない。
- `方法:` の値は `独立サブエージェント` か `自己レビュー` のどちらかをそのまま書く。
- `結果:` の値は `P0 <件数> / P1 <件数> / P2 <件数> / P3 <件数>`（件数は半角の整数、区切りは ` / `）か、指摘が 1 件も無いときの `No findings` のどちらかにする。件数はレビュー役が返した指摘をそのまま数える。妥当でないと判断した指摘や、取り下げられた指摘も件数から除かない。
- レビュー役が取り下げた指摘は、`対応:` に指摘ごとに「取り下げ」の語を含めて書く（例: `P2（…）→ 却下の根拠を渡し、レビュー役が取り下げた`）。照合はこの語で取り下げの記載を見つける。
- `対応:` 以外の 3 行は 1 行に収める。自己レビューにした理由に 2 回分のエラー内容を写すときも、要約するか `；` で区切って 1 行にする。
- `方法:` と `結果:` の値の後ろには、全角括弧の注記 `（…）` を付けてよい。値が `）` で終わるとき、最初の `（` から後ろを注記とみなす（例: `P0 0 / P1 0 / P2 0 / P3 2（前巡の P2 は解消と評価）`）。照合は注記を除いた値を読む。注記以外の表記揺れ（全角のコロン、区切りの ` / ` の欠落、件数の言い換えなど）は書式不備になる。
- `対応:` は最後の行なので、長くなれば次の行へ続けてよい。続きの行は空行を挟まず、`- ` で始めない。空行か `- ` で始まる行が来たら、そこから次の `### ` 見出しまでは記録の外（見出しを付けずに追記された検証の記録など）とみなし、照合では読まない。
- 例（TASK-117 の実記録）:

  ```text
  ### レビュー 4 巡目
  - 方法: 独立サブエージェント
  - 自己レビューにした理由: 該当なし
  - 結果: P0 0 / P1 0 / P2 0 / P3 3
  - 対応: P3 3件とも修正（…）。修正後 bash tests/run.sh PASS 563 / FAIL 0。
  ```

## 照合の規則

照合の対象は、notes で `### 引き渡し` が最後に現れる位置より後にある記録だけである（`### 引き渡し` が無ければ notes 全体）。
再引き渡しでは前回分の記録が notes に残り、巡数が 1 から数え直されることもあるためである。
見出しが `巡目` で終わる記録と、見出しが `レビュー <数>` で始まる記録をレビュー記録として扱う（形が崩れていれば書式不備になる）。
対象の記録のうち notes で最後に現れるものを最終巡とする。
既知の限界として、`2 巡目のレビュー` のように `巡目` で終わらず `レビュー <数>` でも始まらない見出しは、レビュー記録として数えられない。それが実際の最終巡なら、その前の巡が最終巡として扱われる。見出しは書式どおりに書くこと。

`check-review-records` は次の順に判定し、最初に当たったものを `RESULT` にする。

| 順 | `RESULT` | 終了ステータス | 条件 |
| --- | --- | --- | --- |
| 1 | `NO_RECORDS` | 3 | 対象のレビュー記録が 1 巡も無い。レビュー未実施として扱う。 |
| 2 | `FORMAT_ERROR` | 4 | 上の書式から外れた巡がある（見出しの形、4 行の欠落・重複・順序、`対応:` より前にある項目名で始まらない行（理由を複数行に分けた場合を含む）、`方法:` の値、`結果:` が件数として読めない）。 |
| 3 | `NOT_CONVERGED` | 1 | 最終巡の `P0`/`P1`/`P2` が 1 件以上あり、取り下げの記載が無い。または最終巡が `自己レビュー` で `P0`/`P1`/`P2` が 1 件以上ある（自己レビューの巡では取り下げを認めない）。 |
| 4 | `NEEDS_REVIEW` | 5 | 機械的には通過だが、文章の意味を読む必要がある巡がある。`自己レビュー` の巡がある、または最終巡（独立サブエージェント）の `P0`/`P1`/`P2` が 1 件以上あり `対応:` に取り下げの記載がある。 |
| 5 | `OK` | 0 | 上のどれにも当たらない。最終巡の `P0`/`P1`/`P2` が 0 件（または `No findings`）で、自己レビューの巡が無い。 |
| - | `ERROR` | 2 | 引数の誤り、`backlog task view` の失敗など。 |

スクリプトが判定しないもの（`NEEDS_REVIEW` のときに読み手の AI が判断する範囲）は次の 2 つだけである。

- `自己レビュー` の巡の「自己レビューにした理由」が、improvement-work 手順 6 の 2 条件（Agent ツールが自分のツール一覧に無い／Agent ツールの呼び出しが 2 回続けて失敗し、各回の失敗内容が書かれている）のどちらかに当たるか。理由が空欄なら当たらない。
- 最終巡の `P0`/`P1`/`P2` のすべてについて、独立サブエージェントのレビュー役が取り下げたと指摘ごとに書かれているか。取り下げと書かれていない指摘が 1 件でもあれば停止条件に達していない。直したと書かれているだけの指摘は再レビューを経ていないので残っているものとして数える。

## 出力

標準出力の最終行が `RESULT: <値>` である。その前に次の行を出す。

- `REVIEW_ROUNDS: <件数>`：対象のレビュー記録の数。
- `FINAL_ROUND: <見出し>` と `FINAL_RESULT: <結果の値>`：最終巡の見出しと `結果:` の値（読めたときだけ）。
- `FORMAT_ERROR: <見出し>: <理由>`：書式不備の巡ごとに 1 行。
- `NOT_CONVERGED: <見出し>: <理由>`：停止条件に達していない理由。
- `NEEDS_REVIEW: <見出し>: <確認すること>`：AI が判断する巡ごとに 1 行。

診断メッセージは標準エラーに出す。
