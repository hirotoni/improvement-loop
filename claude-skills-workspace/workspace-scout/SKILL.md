# workspace-scout

複数の git リポジトリを直下（深さ1）にクローンした「ワークスペースディレクトリ」を対象に、[improvement-scout](../../claude-skills/improvement-scout/SKILL.md) の手順を opt-in 済みの各リポジトリへ順番に適用する薄いオーケストレーション層である。

**各リポジトリの `.backlog/` はワークスペース全体で共有しない。** 各リポジトリは従来通り独立したバックログを持ち続ける。起票されたタスクもそのリポジトリ自身の `Proposed` に積まれる。本スキルはその上に「複数リポジトリを1回の起動で巡回する」という薄い層を足すだけである。

**このスキル自身も improvement-scout と同じく、このスキルの中でコードを変更しない。** 成果物は各リポジトリに起票されるタスクだけである。

## 前提

- このスキルは `bin/setup-improvement-loop --workspace <ワークスペースディレクトリ>` を実行したワークスペースディレクトリの直下（`.claude/skills/workspace-scout`）に配置される。カレントディレクトリをそのワークスペースルートとして扱う。
- 対象となるのは、ワークスペース直下（深さ1）のサブディレクトリのうち、(a) git リポジトリであり、(b) `<リポジトリ>/.claude/skills/improvement-scout` が実在解決するシンボリックリンクとして存在する（＝ `bin/setup-improvement-loop`（`--workspace` 無し）でそのリポジトリ自身に improvement ループをセットアップ済み）ものだけである。この判定基準以外の新規マーカーファイルは無い。
- 対象外のリポジトリ（未セットアップ、または git リポジトリでないディレクトリ）は黙って対象から外れる。エラーにはしない。

## 手順

### 1. 対象リポジトリを列挙する

散文で `git` や `find` を組み立てず、決定論的なスクリプトを使う。

```bash
.claude/skills/workspace-scout/scripts/list-target-repos
```

標準出力に、opt-in 済みリポジトリの絶対パスが1行1件・ソート済みで並ぶ。0件なら何も出力されない。

- 0件の場合：何もせずその旨を報告して終了する（手順2には進まない）。ワークスペース配下のどのリポジトリにも improvement ループがセットアップされていない、または opt-in （`bin/setup-improvement-loop <リポジトリのパス>` の実行）が済んでいない可能性が高い旨を添える。
- 1件以上の場合：列挙された順（＝パスのソート順）に手順2へ進む。

### 2. 各リポジトリへ順に improvement-scout を適用する

列挙された各リポジトリについて、手順1の出力の順番のまま次を行う。

1. そのリポジトリの絶対パスへ `cd` する。
2. [`claude-skills/improvement-scout/SKILL.md`](../../claude-skills/improvement-scout/SKILL.md) の手順（1〜7）を、**その記述内容を複製せず、そのまま適用する**。観点リストはそのリポジトリ自身の `.claude/skills/improvement-scout/viewpoints.md` を使う。起票も、既存タスクとの照合も、そのリポジトリ自身の `backlog` CLI（そのリポジトリの `.backlog/`）に対して行う。
3. **1リポジトリあたり最大3件という起票上限は、各リポジトリ単位でそのまま適用する。** ワークスペース全体としての合計起票件数の上限は設けない（あるリポジトリで3件起票しても、他のリポジトリの起票可否には影響しない）。
4. そのリポジトリでの結果（選んだ3観点、起票したタスクの一覧（ID・タイトル・優先度）、起票しなかった軽微な指摘 等）を記録しておく。手順3の要約で使う。

各リポジトリの処理を終えたら、必ず次のリポジトリへ進む前にワークスペースルートへ戻る（`cd` の起点を毎回リポジトリ間で混同しないため）。

### 3. 全リポジトリ処理後、要約して報告する

手順2で列挙した順に、リポジトリごとの結果を一覧で報告する。各行には少なくとも次を含める。

- リポジトリの絶対パス（またはワークスペースルートからの相対名）
- 選んだ3観点と選んだ理由
- 起票したタスクの一覧（ID、タイトル、優先度、観点、根拠の `file:line`）
- 起票しなかった軽微な指摘（あれば）
- 承認の手順（`backlog task edit TASK-<n> -s "To Do"` はそのリポジトリのディレクトリで実行する必要がある旨を添える）

タスク本文と報告の言語は会話の言語に合わせる。

## 禁止事項

improvement-scout の禁止事項（`.backlog/`（または `backlog/`）配下の md を直接編集しない、起票したタスクを自分で `To Do` に上げない、監査の中でコードを変更しない、未確認の推測を起票しない 等）を、対象とする全リポジトリに対してそのまま継承する。加えて：

- ワークスペース全体で1つのタスク一覧を扱っているかのように振る舞わない（各リポジトリの `.backlog/` は独立している）。
- あるリポジトリの起票状況（観点の消化度合いなど）を、別のリポジトリの観点選定の根拠に流用しない（観点の消化状況はリポジトリごとの `viewpoint:<slug>` ラベルで独立に管理される）。
- opt-in 済みリポジトリの判定基準（`.claude/skills/improvement-scout` シンボリックリンクの有無）を独自に変えたり、新しいマーカーファイルを作ったりしない。
